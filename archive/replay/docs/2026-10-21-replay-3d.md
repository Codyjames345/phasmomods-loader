# Replay in 3D Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Replay's 2D map panel with real footage of each round's top moments, filmed in the house with the game's camcorder rig and sound, saved as MP4s, and watched together in the lobby on the parked truck's monitor by putting a cassette into the CCTV unit.

**Architecture:** Pure, offline-tested rule headers (`capture_rules.h`, `clip_file.h`, `sync.h`, `media_rules.h`, `director_rules.h`) carry every decision. Game-facing units film (`director.cpp`), listen (`sound.cpp`), encode on a worker thread with Media Foundation (`encoder.cpp`), drive a round (`recorder.cpp`) and run the lobby monitor and tapes (`lobby.cpp`). The host sends one small moment list; every client films and plays its own copy, kept in step by a two-field monitor state.

**Tech Stack:** C++20, MSVC, CMake + Ninja (`build.ps1`), IL2CPP runtime API and engine icalls (`il2cpp::resolve_icall`), MinHook through the host, Media Foundation Sink Writer (H.264 + AAC), WASAPI shared capture, offline tests with `tests/check.h`.

**Spec:** `docs/superpowers/specs/2026-10-21-replay-3d-design.md` (approved 2026-10-21). Every RVA, offset and scene path used below is listed in its "Facts this rests on".

## Global Constraints

- Game build 25811160. Icall signatures are checked by disassembling `UnityPlayer.dll` before binding (IL2CPP ABI gotcha in memory: reference fields store the object itself).
- Nothing is shown or played during a contract. In the lobby nothing plays until a cassette goes in.
- No new window, panel or overlay. Captions exist only inside the footage.
- Footage: 640x360 BGRA, filmed every other frame (30 fps at 60), H.264 about 2 Mbit/s with a keyframe every second, AAC 48 kHz stereo 128 kbit/s.
- A capture starts on a trigger, ends 3 s after the last one, merges triggers less than 5 s apart, and stops at 120 s.
- Top 5 moments, one cassette each; a cassette plays its moment from `in` to `out` once, then comes back out.
- Sound is recorded only when every player in the room runs Replay; otherwise the clip is silent.
- Temporary files in `%LOCALAPPDATA%\PhasmoMods\replays\tmp`; kept clips in `Videos\Phasmophobia Replays`; newest 5 rounds kept; only files carrying the mod's metadata are ever deleted; nothing is written in the game folder.
- Messages on channel 4, at most `PG_MAX_MESSAGE` (511) bytes, header `'R' 'P' 2 type`.
- Sync: a pick starts 250 ms ahead; the later start wins, then the lower actor; drift over 0.25 s seeks.
- Encoder and microphone threads never make IL2CPP calls and are never attached to the runtime.
- Every detour holds a `hooks::Guard`; entry points go through `pg::mod::guarded_*`; every Unity object kept across frames is an `il2cpp::Held` (`held_scan_test`).
- Copy rules for every string a player sees: no em dash, no emoji.
- No git repository: each task ends by running the project's validation, `env -u PSModulePath harness-verify` from `PlayableGhost` (bash).

## Review Focus

- A round whose host does not run Replay, or whose host leaves: after 60 s each client uses its own moments and its tapes play only on its own monitor. Test: `falls_back_after_a_minute_without_a_host_list` in Task 3.
- A player who reaches the lobby late: the host sends the list again on join, and a monitor state that arrives before the list is ignored. Test: `a_state_for_another_round_is_ignored` in Task 3.
- Two players putting in different tapes at the same moment: every monitor ends on the same one. Test: `the_later_pick_wins_then_the_lower_actor` in Task 3.
- A long hitch (alt-tab, loading) during a capture: the sound gets silence for the gap, never repeated audio, and stays aligned with the picture. Test: `a_gap_becomes_silence` in Task 4.
- Photon's millisecond server clock wraps (it is a 32-bit int) during a round. Test: `server_time_unwraps` in Task 1.
