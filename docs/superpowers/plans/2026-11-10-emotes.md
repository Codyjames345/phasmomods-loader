# Emotes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. (The user runs plans inline: superpowers:executing-plans.)

**Goal:** A bundled Emotes mod: an eight-emote wheel on a rebindable key (keyboard, gamepad, VR) that plays a dance and
its music on the player's own body, seen and heard by every player, heard by the ghost as talking, with an eased
third-person camera on screen; and the SDK features any mod needs to do the same.

**Architecture:** Reverse engineering comes first (Tasks 1 to 6) and ends as map entries and `sdk/systems` notes. The
SDK then gains five general features in `sdk/api/` (Tasks 7 to 11), each a documented helper over the map with offline
tests on the fake game. The mod (`mods/emotes/`, Tasks 12 to 18) is pure rules in headers (wheel pick, facing, ending,
its message) plus thin game code that calls the SDK. Each client plays every emote on the emoter's body from one
message on the mod's own channel; the emoter's client decides start, facing and end.

**Tech Stack:** C++20 (`sdk/api`, `sdk/map`, `mods/emotes`), the fake game (`sdk/fake`, `tests/`), REA and the dump
(`re/README.md`) for decompiling, Unity 2022.3.40f1 for the bundle (a new project in `C:\Dev\phasmomods-private\unity\`).

**Spec:** `docs/superpowers/specs/2026-11-10-emotes-design.md`

## Global Constraints

- Every game member used is a map entry with a `///` note, cited by key, decompiled or Unity's documented API;
  `tools\gamecheck.ps1 -IfConfigured -Expect` passes with 0 missing; raw addresses only in gitignored `re/dump/expect`
  and `re/dump/notes`; no obfuscated name anywhere (`no_obfuscated_name_in_the_docs`).
- Never invent game behaviour. If a reverse-engineering task finds the game cannot do what the design assumes (for
  example the keybinds menu cannot take a new row, or Playables are stripped), stop and ask the user before building
  around it.
- No game RPC is sent, no networked object is created, no check on who sent an RPC is weakened. Everything shared goes
  over `send` and `set_receiver` on the mod's channel.
- Player-facing text only in `mods/emotes/i18n/default.json`; every entry the user has not written is `PM_TEXT_TODO`
  and listed in the ledger. No em dash in user-facing text.
- AI makes no assets. The test bundle uses clips from the user's package only; icons, sounds and names wait for the
  user. The wheel's segment shapes are plain geometry built in code (as the Squatter's sheet mesh, a functional mesh);
  its colours and sizes are placeholders in one header for the user to set.
- Every starting value is a named constant with a comment saying it is a starting value, judged with the user in game.
- Tests first, red then green; `.\validate.ps1` after each task; commit messages per CLAUDE.md (imperative subject,
  prose body, Co-Authored-By line). Work on `feature/emotes`, branched from `development`.
- After each task append to `.superpowers/sdd/2026-11-10-emotes/progress.md` (force-added, as the stage 2b ledger).
- Nobody launches the game but the user. Live checks go on the smoke list.

## Review Focus

1. **The wheel interrupted:** the key still held when the pause menu or journal opens, the window losing focus, or the
   player dying with the wheel open. Expected: the wheel closes, nothing plays, look input is back. Owned by Task 13
   (`WheelInput` test `an_interrupted_wheel_plays_nothing`) and Task 16.
2. **The emoter gone mid-emote:** they leave the room, disconnect, or the scene changes. Expected: every other client
   stops the sound and gives the body back, and nothing is left playing. Owned by Task 17 (`a_vanished_emoter_is_cleaned_up`).
3. **Death mid-emote in third person:** the camera returns to first person and the body is handed back before the
   game's death takes it. Owned by Task 17 (`death_ends_the_emote_first`).
4. **Emotes picked in quick succession,** during a blend in or out. Expected: one clip, one sound, one camera move,
   never two stacked. Owned by Task 8 (`a_second_play_replaces_the_first`) and Task 17.
5. **A message for a body that is not there,** or out of range (bad emote index, a player not loaded yet). Expected:
   dropped, no crash. Owned by Task 14 (`bad_messages_are_dropped`).

### Task 13: The emote rules

**Files:**
- Create: `mods/emotes/emote_rule.h` (pure, no game calls)
- Test: `tests/emotes_test.cpp`

**Interfaces:**
- Produces: `inline constexpr int kSegments = 8; inline constexpr float kPickDeadZone = 40.0f /* mouse counts, starting
  value */, kStickDeadZone = 0.5f, kCancelDistance = 0.5f, kFreeArcDegrees = 90.0f;`
  `int segment_for(float dx, float dy, float deadZone)`: -1 inside the dead zone; 0 straight up, then clockwise, each
  segment 45 degrees wide centred on its direction.
  `struct Point { float x, y, z; };` (y up, as Unity).
  `float body_yaw(float bodyYaw, float viewYaw)`: unchanged while the signed shortest angle from body to view is within
  plus or minus `kFreeArcDegrees`; otherwise the body turns so the view sits exactly `kFreeArcDegrees` from it on the
  same side. Called every frame, so the body follows continuously.
  `bool moved_too_far(Point start, Point now)`: horizontal distance strictly greater than `kCancelDistance`.
  `enum class Phase { Idle, Wheel, Emoting };` `struct WheelInput { bool open; int picked; }` and
  `std::optional<int> wheel_step(WheelInput& w, bool held, bool released, bool interrupted, int pickNow)`: opens on
  held, tracks `pickNow`, returns the picked segment on release (none when -1), closes and returns none when
  `interrupted`.
- [ ] **Step 1:** Tests `the_wheel_picks_by_direction` (up 0, right 2, down 4, left 6, up-right 1, inside the dead zone
  -1, the boundary at 22.5 degrees), `the_body_follows_past_ninety` (view 60: body 0; view 120 right: body 30; then view
  0: body stays 30; view 180 reached turning right: body 90; reached turning left: body -90; across the 180/-180 wrap),
  `only_a_move_past_half_a_metre_ends_it` (0.5 exactly: no; 0.51: yes; 3 m straight up: no), `release_plays_the_pick`,
