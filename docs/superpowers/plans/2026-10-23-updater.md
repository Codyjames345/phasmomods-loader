# Updater Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every launcher installs the latest GitHub release of the suite by itself, and the user publishes a release with one script.

**Architecture:** The launcher links Velopack's prebuilt C++ library and checks the repository's releases through its GitHub source on every start. A small decision layer (`tools/update.*`) sits between the launcher and Velopack, so every outcome is unit-tested against a fake. Releases are packed with `vpk` (pinned as a .NET local tool) and published by a GitHub Actions workflow on a `v` tag.

**Tech Stack:** C++20 / MSVC / CMake / Ninja, Velopack C++ library (`velopack_libc`), `vpk` .NET tool, PowerShell, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-23-updater-design.md` (approved 2026-10-23). Read it before starting.

## Global Constraints

- Velopack app id `PhasmoModsLoader`; it installs to `%LOCALAPPDATA%\PhasmoModsLoader`.
- The data directory `%LOCALAPPDATA%\PhasmoMods` (launcher.ini, consent, logs, `bin`) is never written or removed by anything Velopack runs.
- Update source: Velopack's GitHub source for `https://github.com/Codyjames345/phasmomods-loader`, anonymous (no token), pre-releases excluded, `AllowVersionDowngrade = true`.
- No token, password or credential in the repository, the launcher or the package. The workflow uses only its own `GITHUB_TOKEN`.
- Suite version `MAJOR.MINOR.PATCH` in a root `VERSION` file; release tags are `vMAJOR.MINOR.PATCH`. The first version is `0.1.0` (Claude's call).
- The Velopack C++ library is vendored in `third_party/velopack` at one pinned version, and `vpk` is pinned to the same version in `.config/dotnet-tools.json`. Use the newest stable Velopack release that is at least two weeks old on the day it is vendored.
- No file is ever placed in the game folder. No code signing.
- An update check never stops anyone playing: at most 10 seconds, then the launcher carries on with the installed version (Claude's call for the number).
- User-facing text follows the project's copy rules: no em dash, active voice, a control says what it does.
- Every check is one command: `.\validate.ps1`, the same locally and in CI.

## Review Focus

1. **Steam's arguments survive the restart.** `--steam "C:\Program Files (x86)\Steam\steamapps\common\Phasmophobia\Phasmophobia.exe" -arg` must reach the restarted launcher unchanged, spaces and quotes included. Pinned in Task 2's `restart_arguments_round_trip`.
2. **No network.** Offline, or GitHub down, the Steam launch is delayed by at most 10 seconds and the game then starts on the installed version. Pinned in Task 2's `slow_check_is_abandoned`.
3. **A launcher that was not installed by Setup.exe** (a dev build in `dist\PhasmoMods` or `build\`) never tries to update and shows no error. Pinned in Task 2's `not_installed_skips_quietly`.
4. **Two launchers at once** (Steam's and one opened by hand) never apply twice. The second finds the apply refused and carries on. Pinned in Task 2's `apply_refused_carries_on`.
5. **A corrupt or partial download** leaves the installed version in place. Pinned in Task 2's `download_failure_keeps_installed`, and seen for real in Task 8.

### Task 2: The update decision layer

**Files:**
- Create: `tools/update.h`, `tools/update.cpp`
- Test: `tests/update_test.cpp`; register with `pg_test(update tools/update.cpp)` in `CMakeLists.txt`

**Interfaces:**
- Produces, in `namespace pg::update`:
  - `struct Check { enum class Kind { UpToDate, Available, Failed } kind; std::string version; std::wstring error; };`
  - `class Backend { public: virtual ~Backend() = default; virtual bool installed() = 0; virtual std::string current() = 0; virtual Check check() = 0; virtual bool download(const std::string& version, std::wstring& error) = 0; virtual bool apply_and_restart(const std::vector<std::wstring>& arguments, std::wstring& error) = 0; };`
  - `enum class Outcome { NotInstalled, UpToDate, Restarting, CarryOn };`
  - `struct Report { Outcome outcome; std::wstring message; };`
  - `Report run(Backend& backend, const std::vector<std::wstring>& arguments, std::chrono::milliseconds limit);` The check and the download run on a worker thread. When `limit` passes first, `run` returns `CarryOn` with a message, and the worker is told it was abandoned, so it never applies.
  - `std::vector<std::wstring> restart_arguments(const std::vector<std::wstring>& launcherArguments);` The launcher's own arguments after `argv[0]`, unchanged.
- Consumes: nothing from other tasks.

- [ ] **Step 1: Write the failing tests** with a `FakeBackend` whose results each test sets:
  - `not_installed_skips_quietly`: `installed()` false gives `NotInstalled`, an empty message, and no call to `check`.
  - `same_version_is_up_to_date`: `check()` UpToDate gives `UpToDate`, and download is never called.
  - `newer_version_restarts`: Available `"0.2.0"` gives one download of `"0.2.0"`, then `apply_and_restart` with exactly the given arguments, then `Restarting`.
  - `older_version_also_applies`: Available `"0.0.9"` with current `"0.1.0"` is applied the same way (rollback is decided by the user).
  - `check_failure_carries_on`: Failed with error `L"offline"` gives `CarryOn`, and the message contains `offline`.
  - `download_failure_keeps_installed`: a failed download gives `CarryOn`, and apply is never called.
  - `apply_refused_carries_on`: `apply_and_restart` returns false with an error, giving `CarryOn` with that error in the message.
  - `slow_check_is_abandoned`: `check()` sleeps 300 ms against a `limit` of 50 ms. `run` returns `CarryOn` within 200 ms, and after the sleep ends, apply is never called.
  - `restart_arguments_round_trip`: `{L"PhasmoMods Loader.exe", L"--steam", L"C:\\Program Files (x86)\\Steam\\steamapps\\common\\Phasmophobia\\Phasmophobia.exe", L"-screen-fullscreen 0"}` gives the last three elements unchanged. Passing them through `pg::launcher::command_line` and `CommandLineToArgvW` returns the same three.
- [ ] **Step 2: Run** `.\build.ps1; ctest --test-dir build -R update --output-on-failure`. Expected: it fails to compile, because `update.h` is missing.
- [ ] **Step 3: Implement** `run` and `restart_arguments` in `tools/update.cpp`. Messages use the project's copy rules, for example `L"Updated to 0.2.0. Restarting."` and `L"Could not check for updates (offline). Starting the installed version."`.
- [ ] **Step 4: Run** the same command. Expected: every `update` check passes.
- [ ] **Step 5: Commit.**

### Task 6: Build on every push, publish on a tag

**Files:**
- Create: `.github/workflows/build.yml`

**Interfaces:**
- Consumes: `validate.ps1`, `package.ps1` (Task 4), `.config/dotnet-tools.json`.

- [ ] **Step 1: Write the workflow.**
  - It runs on `push` to `main`, on pull requests, and on tags `v*`, on a `windows-latest` runner, with `permissions: contents: read` at the top level.
  - Job `validate`: checkout without persisted credentials, then `.\validate.ps1`.
  - Job `publish`: tags only, `needs: validate`, `permissions: contents: write`. Steps:
    1. `dotnet tool restore`.
    2. Check that the tag equals `v` plus `VERSION`, or fail.
    3. `.\package.ps1`.
    4. `dotnet tool run vpk download github --repoUrl https://github.com/${{ github.repository }}`, for deltas.
    5. `dotnet tool run vpk upload github --repoUrl https://github.com/${{ github.repository }} --publish --tag ${{ github.ref_name }} --releaseName "PhasmoMods ${{ github.ref_name }}" --outputDir dist/releases --token ${{ secrets.GITHUB_TOKEN }}`.
  - Every third-party action is pinned to a full commit SHA, with the version in a comment.
- [ ] **Step 2: Check it**: `actionlint .github/workflows/build.yml` and `zizmor .github/workflows/build.yml`. Expected: no findings. Fix any finding; never suppress one.
- [ ] **Step 3: Prove the tag check can fail.** Run the tag-versus-VERSION step locally as a script with a mismatched tag. Expected: it exits non-zero.
- [ ] **Step 4: Commit.** It is pushed with the next push the user approves. The first green run on GitHub is checked in Task 9.
