# Mod suite: shared host, generic launcher, consent, custom ghosts and the agreed enhancements

Decided by the user on 2026-10-20. This plan records how the work is built and in what order.
Gameplay behaviour is recorded in `docs/design.md`.

## Structure

Everything beyond the playable ghost is a separate mod, and the launcher loads any combination.

| Module | Kind | Holds |
| --- | --- | --- |
| `ModHost.dll` | host | startup checks (binary hashes, runtime), the only MinHook instance, the frame tick, the Photon event channel, mod presence, the consent banner, loading the selected mods |
| `pgcore` | static library linked into every module | IL2CPP access, game and Unity bindings, UI built from game classes, popups, input bindings, the truck map, and the client side of logging, hooks and networking |
| `PlayableGhost.dll` | mod `playable-ghost` | the playable ghost: everything in `docs/design.md`, plus the deception score, per-type senses, the Mimic's copy choice, ghost alerts, hidden salt and crucifixes, and the doppelganger event |
| `CustomGhosts.dll` | mod `custom-ghosts` | Echo, Dullahan, Kikimora, Draugr and Black Shuck: the type roll, evidence, journal pages, results and behaviour, both for the AI ghost and for a ghost player |
| `Replay.dll` | mod `replay` | the top moments of a contract, replayed on the truck map at the end |
| `Afterlife.dll` | mod `afterlife` | the dead investigators' Haunt view (the ghost's eyes) |
| `BiggerLobbies.dll` | mod `bigger-lobbies` | rooms of up to 8 players; lobby cards and the truck monitor paged 1-4 / 5-8 |
| `ModLauncher.exe` | tool | lists the mods in its `mods` folder, remembers which are ticked, starts or attaches the host with that selection |

### Host and mod contract (`core/mod_api.h`, C ABI)

Modules are built with the static CRT, so nothing with an allocator crosses a module boundary:
only plain pointers, integers and C strings.

* A mod exports `pgmod_info` (API version, id, name, network channel, whether it records voice),
  `pgmod_start(const PgHostApi*)`, `pgmod_tick()` and `pgmod_stop()`. All three are called on
  Unity's main thread. A mod catches its own exceptions; nothing unwinds across the boundary.
* The host table gives: logging into the one log, hooks (created through the host's MinHook; a
  second hook on an already hooked target hooks the previous detour, so hooks chain), sending and
  receiving on the mod's own channel of Photon event 197, which modded peers run which mods, a small
  named-service registry for mods that cooperate (the playable ghost asks the custom ghost mod for
  its types), and the paths the mod may use.
* The host starts mods only after consent. A mod that fails to start stays inactive; the others
  run.

### Loading

The launcher copies `ModHost.dll` and the ticked mods into `%LOCALAPPDATA%\PhasmoMods\bin` (a fresh
copy per process, as before) and writes `session-<pid>.txt` beside them, listing the copies. The host
reads the file for its own process id. Loaded another way, the host reads the launcher's
saved selection (`%LOCALAPPDATA%\PhasmoMods\launcher.ini`) against the `mods` folder beside it.
Nothing is ever written to the game folder.

## Consent

A banner covers the main menu as soon as the host is active and blocks it until the player answers.
It covers the whole suite: the ban risk, private lobbies only, voice recording (when a selected
mod records voice), and no liability for lost progress or save data, then lists the selected
mods. **I agree** starts the mods and is remembered for that exact text; changed text asks again.
**Play without mods** leaves the game vanilla until it is restarted. A client's mods (and so its
presence messages) only exist after its player agreed. The Echo uses voice only from peers whose
host reports the voice-recording mod, so nobody who has not agreed is ever recorded.

## Order of work

1. Host, core and launcher split (no behaviour change for the playable ghost).
2. Consent banner.
3. Custom ghosts: type roll and evidence, journal grid (3 x 12, alphabetical, rows 87.5 high),
   journal description pages, results, then each ghost's behaviour:
   * Echo (Spirit Box, Freezing, D.O.T.S.): plays back an investigator's recent phrase near itself;
     dormant after 60 s with nobody speaking near it. The voice pipeline (Vivox participant taps,
     phrase segmentation, chunked transfer, playback through the speaker's own voice settings) lives
     in this mod.
   * Dullahan (EMF, Orbs, Writing): high speed, low turning speed; its speed falls with the angle
     between where it faces and where it must go.
   * Kikimora (UV, Orbs, Writing): moves equipment left on the floor to another room; never in a lit
     room.
   * Draugr (EMF, Orbs, Freezing): never changes favourite room; hunts at 65% once an item has been
     carried out of its room; faster near its room and slower far from it in hunts.
   * Black Shuck (UV, Freezing, D.O.T.S.): in hunts follows the path investigators walked in the
     last 30 s; salt breaks the trail. A ghost player sees the trails instead.
4. Playable ghost: hide salt piles and crucifixes from the ghost player.
5. Playable ghost: deception score on the results screen.
6. Playable ghost: per-type senses (E1), the Mimic's copy choice (E2), alerts (E3).
7. Playable ghost: doppelganger event (the game's unused `GhostEventPlayer`) for every type.
8. Replay mod.
9. Afterlife mod.
10. Bigger lobbies mod.

Every step builds, passes `validate.ps1` through `harness-verify`, and records in `FINDINGS.md`
what has only been verified against decompiled code.
