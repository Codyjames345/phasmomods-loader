# The Squatter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the Squatter to Custom Ghosts: a person in a cloth-simulated bedsheet who chases players out of the house, clumsily and in the user's voice, with no paranormal activity.

**Architecture:** A pure rule header (`squatter_rule.h`) decides phases, speed, lines and door locking, and is tested offline. Small game-facing files apply it from Custom Ghosts' tick, on the master, and tell other clients what to show through the SDK's one channel. New engine and game access goes through documented map entries. A throwaway test of the three unproven engine features comes first, and nothing else starts until it passes.

**Tech Stack:** C++20, the project's SDK map and resolver, Unity 2022.3.40f1 (bundle building only), Mixamo clips, UnityPy for offline asset facts.

**Spec:** `docs/superpowers/specs/2026-11-04-squatter-design.md`. Read it and `CLAUDE.md` before any task.

## Global Constraints

- `CLAUDE.md` binds every task. Where it and this plan disagree, ask the user. The spec's "Rules this ghost breaks on purpose" lists the only exceptions.
- Never launch the game, inject, or write in the game folder. Every in-game check goes on the smoke list for the user, who is told the ban risk first.
- Every claim about game behaviour cites a map key and comes from decompiled code. If a behaviour is unknown, reverse engineer it. Never guess.
- Nothing in the SDK or docs names an obfuscated member, an address or an offset, or describes the anti-cheat. Raw numbers go in gitignored `re/dump/`.
- Never send a game RPC by name or invoke an RPC body. Never change `Difficulty.friendlyGhost`. Never call `Player.BeginDeathSequence` for a dead player or on a friendly ghost's difficulty.
- Counts, lists and names the game holds (exits, sprint speed, kill reach) are read at runtime. Fail closed only when they can't be read.
- AI writes no player-facing text or creative choices. Journal text is `PM_TEXT_TODO` and listed for the user. The user picks every clip and records or supplies every sound.
- Downloaded Mixamo files and the bundle never enter the repo. Every release carries the compiled clips, because public releases don't drop features (user, 2026-11-04). Stock clips enter the repo only when the user confirms their licence.
- Work on `feature/squatter`, branched from `development`. The user asked on 2026-11-04 for this build to go to `development` when ready. Ready means all offline checks pass and the user reports the in-game smoke list passed; then merge and push without a further go. A push to `development` publishes a pre-release, so nothing is pushed earlier. `main` and releases need the user's go at that moment.
- Commit messages: imperative subject under about 72 characters, then prose saying what was missing and why (no bullet lists, no conventional-commit prefixes), ending with the attribution line.
- Each task: tests first, then `.\validate.ps1`. Tasks that add or move map entries also run `.\tools\gamecheck.ps1 -IfConfigured -Expect` and show the result. Append what you did and any behaviour difference to `.superpowers/sdd/squatter/progress.md`.
- Stop and report BLOCKED or NEEDS_CONTEXT rather than guess at an architectural choice.

## Review Focus

- **A player disconnects, or dies, while being chased:** the Squatter drops them and carries on, and the door locks once the remaining living players are out. Test in Task 2.
- **A player steps out, then walks back in before everyone is out:** the door stays unlocked and they are chased again. Test in Task 2.
- **The master leaves mid-chase:** the new master continues from the shared phase rather than resetting to lurking or locking the doors twice. Test in Task 7.
- **A recording or clip is missing or malformed:** a missing line stays silent and one bad WAV keeps its slot silent, while a missing or broken bundle disables the whole Custom Ghosts mod with the error in the log, as for any mod with an error (user, 2026-11-06). Tests in Tasks 3 and 5.
- **The Squatter is forced by something else in the game** (a cursed possession's forced state change, a Monkey Paw): it produces no hunt, event or kill attempt on a friendly ghost's difficulty. Test in Task 4.

```cpp
enum class Phase : uint8_t { Lurking, Chasing, Searching, AtHidingPlace, LockedOut, Moping, Excited, Following };
enum class Move : uint8_t { Run, Duck, Weave, Roll, Parkour, Stumble };
enum class Lines : uint8_t { Lurk, Chase, Search, Hiding, Catch, Door, Tired, Mope, Excited, Friendly };

struct Facts {
  bool friendly;        // Difficulty.friendlyGhost
  bool seesPlayer;      // a target is in sight now
  bool tracksPlayer;    // it still knows where a target is
  bool targetHiding;    // it knows its target is in a hiding place
  int livingInside;     // living players inside the house
  bool actFinished;     // the get-up clip has ended (Excited)
};
Phase next_phase(Phase now, const Facts& f);
Phase first_phase(bool friendly);                     // Lurking or Moping
bool doors_lock(Phase now, const Facts& f);           // this frame is the one that locks them
bool may_kick(Phase now, bool friendly, bool targetAlive, float distance, float reach);
float move_speed(float sprintSpeed, Move m);          // metres per second
float average_chase_speed(float sprintSpeed);         // over one cycle of kMoveCycle
Move move_at(float seconds);                          // deterministic from a seed-offset time
Lines lines_for(Phase now);
bool tired_taunt_due(bool targetCanSprint, bool targetCouldSprintBefore, float secondsSinceTaunt);
int pick_line(int count, int last, uint32_t roll);    // -1 when count is 0; avoids repeating last
```

- [ ] **Step 1: Write the failing tests** in `tests/squatter_test.cpp`:
  - `lurks_until_it_sees_someone`: `next_phase(Lurking, {seesPlayer=false})` stays; with `seesPlayer=true` becomes `Chasing`.
  - `search_and_chase_alternate`: `Chasing` with `tracksPlayer=false` becomes `Searching`; `Searching` with `seesPlayer=true` becomes `Chasing`, and with `targetHiding=true` becomes `AtHidingPlace`. `AtHidingPlace` with `targetHiding=false, seesPlayer=true` becomes `Chasing`.
  - `door_locks_only_when_everyone_is_out`: for each of `Chasing`, `Searching`, `AtHidingPlace`: `doors_lock` is true only at `livingInside == 0`. `Lurking` at 0 is false, because nobody was chased.
  - `walking_back_in_keeps_the_door_open`: `livingInside` going 1, then 0 in a later call only: false until then. Chasing with `livingInside` rising from 1 to 2 is false.
  - `a_dropped_target_does_not_stop_the_door`: the chased player's disconnect is only `livingInside` falling, so reaching 0 while `Chasing` locks.
  - `locked_out_is_final`: `LockedOut` stays under every `Facts`, and `doors_lock(LockedOut, ...)` is false, so they lock once.
  - `friendly_never_chases_or_kicks`: `first_phase(true) == Moping`; `Moping` with `seesPlayer` becomes `Excited`; `Excited` with `actFinished` becomes `Following`; no friendly sequence reaches `Chasing`, `AtHidingPlace` or `LockedOut`; `may_kick(p, true, true, 0, 1)` is false for every phase; `doors_lock` is false.
  - `kick_needs_a_living_target_in_reach`: `may_kick(Chasing, false, false, 0, 1)` is false; distance above reach is false; below is true; `Lurking` is false.
  - `speed_stays_just_under_sprint`: `average_chase_speed(s) < s` and `average_chase_speed(s) > 0.85f * s` for `s` of 2, 3 and 4; `move_speed(s, Stumble) == 0`; `move_speed(s, Roll) > move_speed(s, Run)`; `move_speed(s, Duck) < move_speed(s, Run)`.
  - `tired_taunt_fires_once_per_lapse`: true on the edge of `targetCanSprint` going false after a cooldown; false while it stays false within the cooldown; false when `targetCanSprint` is true.
  - `lines_match_the_phase`: each phase maps as the spec says, including `LockedOut` to `Door`, `Moping` to `Mope`, `Excited` to `Excited`, and `Following` to `Friendly`.
  - `picks_never_repeat_and_handle_nothing`: `pick_line(0, -1, r) == -1`; `pick_line(1, 0, r) == 0`; for `count >= 2` it never returns `last`.
- [ ] **Step 2: Run the test to see it fail.** Run: `.\build.ps1` then `ctest --test-dir build -R squatter --output-on-failure`. Expected: the build fails because `squatter_rule.h` is missing.
- [ ] **Step 3: Implement `squatter_rule.h`.** Starting values, to be tuned with the user in game: `kSprintMargin = 0.95`, and multipliers on `sprintSpeed * kSprintMargin` of Run 1.0, Duck 0.7, Weave 0.9, Roll 1.3, Parkour 1.1, Stumble 0. `move_at` walks a fixed `kMoveCycle` table in which Run dominates. Comment each value as a starting value.
- [ ] **Step 4: Run the test to see it pass,** with the same command. Expected: `squatter_test` passes.
- [ ] **Step 5: Run `.\validate.ps1` and commit.**
